# OSCC算法实现指南

## 项目概述

本项目旨在将现有的基于ns-3的WebRTC仿真平台改造为OSCC（Order-Sensitive Congestion Control）算法实现。当前代码已实现"套壳GCC"的μ缩放实验框架，需要将静态μ值改造为基于传输机会和网络反馈的动态自适应μ调整机制。

## 二、OSCC算法核心机制

### 2.1 算法目标

根据数据包的帧内发送顺序（FISO）计算其传输机会ℛ，动态调整带宽缩放因子μ：

- 传输机会大的包（帧前部）：采用激进策略（μ较大）
- 传输机会小的包（帧后部）：采用保守策略（μ较小）

### 2.2 核心公式

传输机会计算：
$$
\mathcal{R}_{i,j} = \max\left(0, \frac{(Ddl_j - t_{now}) - t_{pkt}}{RTT}\right)
$$

帧内μ调整（基于同一ℛ组的丢包率对比）：
$$
\mu_t = \mu_{t-1} + \varepsilon \cdot \text{sign}(L_{i,j-1} - L_{i,j})
$$

帧间μ调整（基于整帧QoE对比）：
$$
\mu_t = \mu_{t-1} + \varepsilon \cdot \text{sign}(QoE_j - QoE_{j-1})
$$

最终发送速率：
$$
R_t^* = \mu_t \cdot R_t \quad \text{where } \mu_t \in [\mu_{min}, \mu_{max}]
$$

### 2.3 QoE计算模型

$$
QoE_j = 0.2 \cdot QoE_{recv} + 0.2 \cdot QoE_{delay} + 0.3 \cdot QoE_{loss} + 0.3 \cdot QoE_{ddl}
$$

其中：
- $QoE_{recv} = 100 \times U_t$（带宽利用率）
- $QoE_{delay} = 100 \times \frac{D_{max} - D_{95th}}{D_{max} - D_{min}}$
- $QoE_{loss} = 100 \times (1 - L_t)$
- $QoE_{ddl} = 100 \times (1 - Ddl_{miss})$

### 2.4 HAFA算法流程

```
初始化: μ₀ = 1.0

对于每个帧 j:
    对于帧内每个ℛ组（按ℛ递减顺序）:
        1. 发送该组所有包
        2. 收集该组丢包率 Lᵢ,ⱼ
        3. 帧内调整:
           if (存在历史 Lᵢ,ⱼ₋₁):
               if Lᵢ,ⱼ < Lᵢ,ⱼ₋₁: μ += ε  // 表现更好，更激进
               else:              μ -= ε  // 表现更差，更保守
           elif (ℛ > ℛ_max,j₋₁):
               μ += ε  // 新出现的高ℛ组，探索性增加
        4. 约束: μ = clip(μ, μ_min, μ_max)
        5. 应用: R* = μ × R_gcc
    
    帧传输完成后:
        计算 QoEⱼ
        帧间调整:
           if QoEⱼ > QoEⱼ₋₁: μ += ε
           else:             μ -= ε
        约束: μ = clip(μ, μ_min, μ_max)
```

## 三、改造方案

### 3.1 新增类：OSCCController

在`webrtc-TFMN_QoE.cc`中新增OSCC核心控制器类：

```cpp
class OSCCController {
public:
    OSCCController();
    
    // 核心接口
    double GetMuForPacket(uint32_t frame_id, uint32_t Rt, double current_loss);
    void OnRtGroupComplete(uint32_t frame_id, uint32_t Rt, double group_loss);
    void OnFrameComplete(uint32_t frame_id, double frame_qoe);
    
private:
    // 参数
    double epsilon_ = 0.02;          // 调整步长
    double mu_min_ = 0.5;
    double mu_max_ = 1.5;
    double current_mu_ = 1.0;
    
    // 历史记录
    std::map<uint32_t, double> last_frame_rt_loss_;     // 上一帧各Rt组丢包率
    std::map<uint32_t, double> current_frame_rt_loss_;  // 当前帧各Rt组丢包率
    double last_frame_qoe_ = 0.0;
    uint32_t last_frame_max_rt_ = 0;
    
    // 内部方法
    void AdjustMuIntraFrame(uint32_t Rt, double current_loss);
    void AdjustMuInterFrame(double current_qoe);
    double ClipMu(double mu);
};
```


### 3.5 修改数据流

当前流程（静态μ）：
```
启动时设置固定μ → 整个仿真使用同一μ值
```

改造后流程（动态μ）：
```
包到达 → FrameManager.ProcessPacketArrival()
       → 计算当前包的Rt
       → OSCCController.GetMuForPacket(frame_id, Rt, loss)
       → 获取该Rt组应使用的μ值
       → WebrtcSender.UpdateMuDynamic(μ)
       → 应用到GCC发送速率

Rt组完成 → OSCCController.OnRtGroupComplete()
         → 帧内μ调整

帧完成 → FrameManager.OnFrameComplete()
       → OSCCController.OnFrameComplete(frame_id, qoe)
       → 帧间μ调整
```

### 3.6 修改批处理脚本

`webrtc-FMN-TFMN_QoE.cc`改为：
- 不再遍历不同μ值
- 启用OSCC自适应模式
- 收集动态μ变化日志

## 五、关键约束

1. μ值范围：[0.5, 1.5]
2. 调整步长ε：建议0.02-0.05
3. 首帧策略：μ₀ = 1.0（中性启动）
4. 新Rt组策略：当出现上一帧不存在的高Rt值时，μ += ε（探索性增加）
5. 稳定性：通过clip操作防止μ震荡
